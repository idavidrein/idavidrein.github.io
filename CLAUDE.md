# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Personal site for David Rein (idavidrein.com), deployed to Netlify. `index.html` is hand-written (except the writing list, see below); blog posts under `/posts/*.html` and the `/writing.html` archive are generated by a small Python script.

## Commands

- Build: `python3 build.py` (regenerates every HTML in `posts/` and every OG image in `posts/og/` from `content/posts/*.md`, then regenerates `writing.html` and rewrites the homepage writing list from `content/writing.yaml`)
- Install deps: `pip install -r requirements.txt` — `markdown`, `PyYAML`, `Pillow`
- Local preview: open `index.html` directly, or run any static file server from repo root
- Netlify production build (configured in `netlify.toml`): `pip install -r requirements.txt && python3 build.py`, publishing `.` (the repo root itself is the site)
- PR deploy previews are posted automatically by `.github/workflows/netlify-deploy-preview.yml`

There is no test suite or linter. There is no `package.json`.

## Architecture

### Two parallel content trees

- `content/posts/*.md` — Markdown sources with YAML frontmatter (`title`, `date`, `slug`, `description`). These are the editable source of truth.
- `posts/*.html` — Generated output. **Committed to the repo** because Netlify publishes the repo root directly. If you edit a post, run `python3 build.py` and commit both the `.md` and the regenerated `.html` (plus the OG image).
- `posts/og/<slug>.png` — Auto-generated 1200×630 Open Graph cards, rendered with Pillow using `files/fonts/EBGaramond.ttf`. The title is auto-sized to fit; site name "idavidrein.com" sits at the bottom.

`index.html` is hand-written **except** the writing list. The hero, About, and Research highlights sections are edited by hand. The "Selected writing & talks" list lives between the `<!-- WRITING:START -->` and `<!-- WRITING:END -->` markers and is rewritten by `build.py` on every run — do not hand-edit between those markers; edit `content/writing.yaml` instead.

### The writing index — `content/writing.yaml`

`content/writing.yaml` is the single source of truth for every essay, external post, talk, and podcast appearance. It feeds two generated outputs:

- `writing.html` (repo root) — the full, searchable/filterable archive. Server-rendered list of every entry; `writing.js` does client-side search (title/description/tags) and type filtering. With JS disabled, all entries still show (graceful degradation).
- The homepage list — `build.py` injects the curated subset between the `WRITING:START`/`WRITING:END` markers in `index.html`.

Entry schema (validated by `load_writing`): `title`, `url`, `date`, `type`, `description` are required; `tags` and `featured` are optional. The header comment in `writing.yaml` documents each field. Notes:

- `url` starting with `/` (or `#`) is treated as internal (in-tab); anything else opens in a new tab with `rel="noreferrer"`.
- `date` may be `YYYY-MM-DD` or a bare `YYYY`. Only the year is ever displayed; the full date refines sort order within a year. Entries are sorted newest-first.
- `type` must be one of `essay | external | talk | podcast` (drives the filter chips and type label).
- The homepage shows up to 5 entries marked `featured: true` (newest-first); if none are featured it falls back to the 5 most recent.

`writing.html`, the injected homepage block, `posts/*.html`, and OG images are all **committed** (Netlify publishes the repo root directly). After editing `writing.yaml` or any post, run `python3 build.py` and commit the regenerated files.

### `build.py` — non-obvious transforms

The build pipeline does more than markdown→HTML. When editing it, know that each post goes through these steps in order:

1. `parse_frontmatter` — extracts YAML between `---` fences.
2. `markdown.Markdown(extensions=["footnotes", "smarty"])` — renders body, including python-markdown's default footnote block at the bottom.
3. `process_footnotes` — **rewrites** that bottom-of-page footnote block into inline popup `<span>`s. The numbered `<sup>` references are replaced with `<span class="footnote-ref">` wrappers containing the footnote content inline. The bottom `<ol>` is removed. The regex handles repeated refs (`fnref2:`, `fnref3:`, …) for footnotes cited more than once.
4. `open_links_in_new_tab` — blanket regex that adds `target="_blank" rel="noreferrer"` to every `<a `. This means **all** anchors (including footnote popup links) open in a new tab. If you ever add internal anchors that should stay in-tab, this rule will need refining.
5. `generate_og_image` — writes `posts/og/<slug>.png`.

The HTML template is a Python f-string constant (`TEMPLATE`) at the top of `build.py`. Each post links to `../styles.css`, `../footnotes.js`, and `../files/favicon/...` (relative paths), so anything in `posts/` must stay one directory deep.

### Footnote popup behavior (`footnotes.js`)

Footnotes don't render at the bottom of the page — they appear as superscript numbers that show their content in a popup positioned above the reference. `footnotes.js` handles three interaction modes:

- Click/tap (mobile and desktop): toggles `.active` class, dismisses on outside click. Clicks on links inside the popup are allowed through.
- Hover (`(hover: hover)` only, i.e. desktop with a mouse): toggles `.hover` class.
- Keyboard focus: same as hover.

`positionPopup` clamps the popup horizontally within `.post-body` so it can't overflow. This is why the popup must be a child of `.footnote-ref` and `.footnote-ref` must live inside `.post-body`.

### Styling

Single `styles.css` for the landing page, posts, and `writing.html`. CSS custom properties at `:root` (`--bg`, `--ink`, `--muted`, `--accent`, `--line`) define the palette. Font stack starts with Iowan Old Style; EBGaramond is only used inside generated OG images. The writing-archive controls (`.writing-search`, `.filter-chips`/`.chip`, `.entry-meta`/`.entry-type`/`.tag`) and the homepage `.section-head`/`.see-all` live in the same file.

## Adding a new post

1. Create `content/posts/<slug>.md` with frontmatter (`title`, `date: YYYY-MM-DD`, `slug`, `description`).
2. Add an entry to `content/writing.yaml` (`type: essay`, `url: /posts/<slug>.html`, plus `tags` and `featured` as desired).
3. Run `python3 build.py` — this regenerates the post, its OG image, `writing.html`, and the homepage list.
4. Commit the `.md`, the generated `posts/<slug>.html`, `posts/og/<slug>.png`, `writing.yaml`, the regenerated `writing.html`, and `index.html`.

## Adding non-post writing (external posts, talks, podcasts)

Add an entry to `content/writing.yaml` with the appropriate `type`, run `python3 build.py`, and commit `writing.yaml`, `writing.html`, and `index.html`. No `index.html` hand-editing.
